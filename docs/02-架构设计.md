# 架构设计

## 整体架构

本项目采用经典的**分层架构**设计，从上到下分为五层：

```
┌─────────────────────────────────────┐
│    表现层 (Presentation Layer)       │  ui.py
├─────────────────────────────────────┤
│    业务逻辑层 (Business Logic)       │  logic.py
├─────────────────────────────────────┤
│    任务执行层 (Task Execution)       │  tasks.py
├─────────────────────────────────────┤
│    工具层 (Utility Layer)           │  adb_utils.py + ai_client.py
├─────────────────────────────────────┤
│    外部接口 (External Interface)     │  ADB + 智谱AI API
└─────────────────────────────────────┘
```

## 层级职责

### 1. 表现层 (ui.py)

**职责**: 用户界面和交互

**核心类**: `MainApp(tk.Tk)`

**主要功能**:
- 窗口管理和布局
- 配置页面（全局参数设置）
- 任务列表页面（任务CRUD）
- 用户交互响应

**关键方法**:
```python
show_config_page()      # 显示配置页
show_task_page()        # 显示任务列表
create_card(idx, data)  # 创建任务卡片
refresh_list()          # 刷新任务列表
```

**设计亮点**:
- 双页面架构（配置页/任务页）
- 动态参数渲染（根据任务类型自动生成表单）
- 实时保存机制（FocusOut自动保存）

---

### 2. 业务逻辑层 (logic.py)

**职责**: 数据管理和任务调度

**核心类**: `AppLogic`

**主要功能**:
- 配置管理（加载、保存、环境变量注入）
- 任务管理（增删改查）
- 任务执行（单任务、批量任务、循环执行）

**关键方法**:
```python
load_data()                    # 加载配置文件
save_data()                    # 保存配置文件
apply_config_to_env()          # 将配置注入环境变量
add_task()                     # 添加新任务
update_task_type(idx, type)    # 更新任务类型
run_single_task(idx)           # 运行单个任务
run_all_tasks()                # 批量运行任务（支持循环）
```

**设计亮点**:
- 配置持久化（JSON格式）
- 环境变量机制（任务运行时读取配置）
- 循环执行支持（loop_count配置）

---

### 3. 任务执行层 (tasks.py)

**职责**: 任务具体实现

**核心基类**: `GameScriptBase`

**六大任务类**:
1. `FarmingTask` - 种田（智能版）
2. `GatheringTask` - 采集（全自动版）
3. `ProcessingTask` - 加工（普通/特殊工坊）
4. `CookingTask` - 做菜（固定位置/盲盒模式）
5. `OrderTask` - 订单（自动交付）
6. `DandelionTask` - 蒲公英（自动收发）

**基类设计 - 模板方法模式**:
```python
def run(self):
    self.reset_state()          # 1. 复位
    self.navigate_to_target()   # 2. 定位
    self.execute()              # 3. 执行（子类实现）
    self.exit_interface()       # 4. 退出
```

**设计模式**:
- **模板方法模式**: 基类定义流程骨架，子类实现具体步骤
- **注册表模式**: `SCRIPT_REGISTRY`实现任务类型的动态查找
- **配置驱动**: 每个任务类通过`PARAM_CONFIG`声明所需参数

**任务注册机制**:
```python
SCRIPT_REGISTRY = {
    t.LABEL: t for t in [FarmingTask, GatheringTask, ...]
}
```

### 4. 工具层

#### 4.1 ADB工具 (adb_utils.py)

**职责**: 封装ADB命令和操作

**核心功能**:

| 功能模块 | 函数 | 说明 |
|---------|------|------|
| 设备管理 | `auto_select_device()` | 自动检测和锁定设备 |
| 基础操作 | `adb_click(x, y)` | 点击 |
|  | `adb_swipe(x1, y1, x2, y2)` | 滑动 |
|  | `adb_zoom_out()` | 双指缩放 |
| 截图 | `adb_screenshot(path, crop_box)` | 截图（支持裁剪） |
| 高级操作 | `run_continuous_drag(points)` | 连续拖拽（Monkey脚本） |
| 命令解析 | `execute_multiline_adb(text)` | 多行ADB命令解析执行 |
| 图像处理 | `stitch_images(left, right, output)` | 图片拼接 |

**设计亮点**:
- **多设备支持**: 自动添加`-s <device_id>`参数
- **自动连接**: 检测不到设备时自动尝试连接常见端口
- **Monkey脚本**: 实现丝滑连续拖拽（种田收割核心技术）
- **裁剪截图**: 减少AI识别的图像面积，提升准确率

**Monkey脚本示例**:
```python
# 实现连续拖拽，解决Android input命令无法实现的连续划动
type= user
count= 10
speed= 1.0
start data >>
DispatchPointer(0, 0, 0, 100, 100, 0, 0, 0, 0, 0, 0, 0)  # 按下
UserWait(1200)                                            # 等待
DispatchPointer(0, 0, 2, 200, 200, 0, 0, 0, 0, 0, 0, 0)  # 移动
DispatchPointer(0, 0, 1, 200, 200, 0, 0, 0, 0, 0, 0, 0)  # 抬起
```

#### 4.2 AI客户端 (ai_client.py)

**职责**: 与智谱AI大模型通信

**核心功能**:

```python
get_client()                        # 获取OpenAI客户端（每次新建，防止Token过期）
convert_image_to_webp_base64()      # 图片压缩和编码
build_messages()                    # 构建API请求消息
query_vlm(image, prompt)            # 核心接口：发送图片+提示词，返回识别结果
```

**设计亮点**:
- **Token刷新**: 每次调用都创建新客户端，防止JWT过期
- **图片压缩**: 超过1024px自动缩放，节省Token并加速
- **WebP格式**: 使用WebP格式，比PNG/JPG体积小
- **低温度**: temperature=0.1，减少随机性，提升识别稳定性

## 数据流转

### 配置数据流

```
用户输入 (UI)
    ↓
logic.update_config()
    ↓
data.json (持久化)
    ↓
logic.apply_config_to_env()
    ↓
os.environ (环境变量)
    ↓
任务执行时读取
```

### 任务执行流

```
UI: 点击"运行"
    ↓
logic.run_single_task(idx)
    ↓
从SCRIPT_REGISTRY查找任务类
    ↓
实例化任务类: cls(params)
    ↓
调用: instance.run()
    ↓
    ├─ reset_state()       [ADB操作]
    ├─ navigate_to_target() [ADB操作]
    ├─ execute()           [ADB + AI识别]
    │    ├─ adb_screenshot()
    │    ├─ query_vlm()
    │    └─ 决策 + ADB操作
    └─ exit_interface()    [ADB操作]
```

### AI识别流

```
任务需要识别
    ↓
adb_screenshot(crop_box) [可选裁剪]
    ↓
query_vlm(image, prompt)
    ↓
    ├─ 图片压缩 (WebP)
    ├─ Base64编码
    ├─ 构建消息体
    └─ 调用智谱AI API
    ↓
返回识别结果 (字符串)
    ↓
正则提取数据
    ↓
决策逻辑
    ↓
执行ADB操作
```

## 设计模式应用

### 1. 模板方法模式 (Template Method)
- **位置**: `GameScriptBase.run()`
- **目的**: 定义统一的执行流程，子类只需实现`execute()`

### 2. 注册表模式 (Registry)
- **位置**: `SCRIPT_REGISTRY`
- **目的**: 任务类型与类的映射，支持动态查找

### 3. 策略模式 (Strategy)
- **位置**: 不同任务类
- **目的**: 每个任务类是一种执行策略

### 4. 工厂模式 (Factory)
- **位置**: `logic.run_single_task()`
- **目的**: 根据任务类型动态创建任务实例

### 5. 单例模式 (Singleton)
- **位置**: `adb_utils.CURRENT_DEVICE_ID`
- **目的**: 全局唯一的设备ID

## 扩展性设计

### 如何添加新任务类型

1. 继承`GameScriptBase`
2. 定义`LABEL`和`PARAM_CONFIG`
3. 实现`execute()`方法
4. 添加到`SCRIPT_REGISTRY`

示例：
```python
class NewTask(GameScriptBase):
    LABEL = "7. 新任务"
    PARAM_CONFIG = {
        "param1": {"label": "参数1", "type": "string", "default": "值"}
    }
    
    def execute(self):
        # 实现任务逻辑
        pass

# 注册
SCRIPT_REGISTRY[NewTask.LABEL] = NewTask
```

### 如何添加新的ADB操作

在`adb_utils.py`中添加新函数：
```python
def adb_long_press(x, y, duration=1000):
    run_adb_cmd(["shell", "input", "swipe", str(x), str(y), str(x), str(y), str(duration)])
```

### 如何自定义AI提示词

每个任务的`execute()`方法中可自由编写提示词：
```python
prompt = """
请识别图片中的状态：
- 如果显示"收获"，返回harvest
- 如果显示"种植"，返回plant
"""
state = query_vlm(screenshot_path, prompt)
```

## 配置与环境变量

### 环境变量注入机制

```python
# logic.py
def apply_config_to_env(self):
    for k, v in self.config.items():
        os.environ[k] = str(v)
```

### 任务读取配置

```python
# tasks.py
self.s_delay = float(os.environ.get("small_delay", 1.5))
self.b_delay = float(os.environ.get("big_delay", 8.0))
```

这种设计使得配置修改后无需重启程序即可生效。

## 异常处理

### 分层异常处理

| 层级 | 处理方式 |
|-----|---------|
| UI层 | 弹窗提示用户 |
| Logic层 | 捕获并返回错误信息 |
| Task层 | 打印日志，继续执行 |
| 工具层 | 返回None或空字符串 |

### 容错设计

- **设备检测失败**: 自动尝试连接常见端口
- **截图失败**: 重置设备ID，下次重新检测
- **AI识别失败**: 返回默认值（如9999）
- **参数解析失败**: 使用默认值或跳过

## 性能优化

### 1. 图片压缩

- 使用WebP格式

- `CURRENT_DEVICE_ID`避免重复检测

### 4. 批量操作
- 贪心算法一次性填满生产位
- 减少UI交互次数
